# Спринт 01. Каркас приложения и модель данных

## Цель

Подготовить запускаемый каркас React, ASP.NET Core API и PostgreSQL. Зафиксировать схему, в которой каждый внешний факт связан с конкретным источником, а пользовательские поля хранятся отдельно от обновляемых фактов.

## Работы

1. Создать структуру `backend/Api`, `Application`, `Domain`, `Infrastructure` и `frontend/src/pages`, `features`, `shared` согласно [архитектуре](../architecture.md). Настроить TypeScript, каркас маршрутизации и API-клиента, генерацию OpenAPI из фактических маршрутов. Обработку сессии и CSRF в клиенте завершить в спринте 06.
2. Подготовить `compose.yaml`, `.env.example`, конфигурацию подключения к PostgreSQL и постоянный volume. Реальные пароли, мастер-ключ и API-ключи не добавлять в репозиторий.
3. Настроить EF Core, миграции и применение миграций при развёртывании. Определить UTC для дат и UUID для идентификаторов.
4. Создать таблицы `suppliers`, `supplier_facts`, `fact_sources`, `supplier_sources`, `supplier_products`, `supplier_prices`, `supplier_images`, `discovery_runs`, `ai_provider_settings`. Сводные поля поставщика и индексируемые товары/цены обновлять вместе с фактами.
5. Установить индексы для официального домена, названия и региона без домена, даты добавления, избранного, города, категории и товаров. Предусмотреть защиту от параллельного создания одного поставщика по правилам дедупликации.
6. Описать в домене `official`, `external`, `missing`, текущий факт и альтернативные наблюдения. Сводное `suppliers.name` должно ссылаться по смыслу на текущий подтверждённый факт `name`; название без источника не считается пригодным для поставщика.
7. Добавить единый формат ошибок Problem Details с `code` и `traceId`, проверку готовности `GET /api/v1/health/ready` с доступом к PostgreSQL и базовое логирование без секретов.

## Проверяемый результат

- `compose.yaml` поднимает все три компонента; backend применяет миграции и отвечает на запрос готовности после подключения к базе.
- Backend подключается к пустой базе без ошибок; схема содержит таблицы, связи и индексы для фактов, источников и пользовательских полей. API списка поставщиков появится в спринте 05, страница базы — в спринте 08.
- Повторный запуск контейнеров сохраняет данные PostgreSQL; повторное применение миграций не создаёт дубли схемы.
- Сгенерированный OpenAPI отражает реализованные маршруты, а ошибки API имеют согласованный формат.
