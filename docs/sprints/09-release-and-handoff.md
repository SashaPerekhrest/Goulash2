# Спринт 09. Сквозная проверка, публикация и сдача

## Цель

Получить доступный по HTTPS прототип, который можно запустить по README и показать по сценарию исходного задания.

## Работы

1. Собрать frontend, backend и PostgreSQL через `compose.yaml`; проверить постоянное хранение БД, ожидание её готовности и применение миграций на чистом окружении и после перезапуска.
2. Настроить HTTPS через reverse proxy, адрес приложения, cookie `Secure` и секреты окружения. Убедиться, что API-ключ, пароль администратора и мастер-ключ отсутствуют в репозитории и клиентской сборке.
3. Пройти пользовательский путь: вход → настройка и проверка провайдера → поиск с фильтрами → список лидов → отдельный JSON-профиль на каждого → карточка и справочные ссылки → избранное и заметка → нахождение компании в локальной базе.
4. Проверить крайние случаи: пустой поиск, отсутствующий ключ, пустая база, нулевой список, некорректный JSON первого этапа, ошибка одного профильного запроса, тайм-аут, потеря сессии, неизвестный ID и неработающая фотография.
5. Проверить серверную валидацию числовых границ фильтров, локальную фильтрацию каталога, пагинацию и стабильную сортировку. Убедиться, что фильтры поиска поставщиков передаются первому запросу и не применяются сервером после профиля.
6. Проверить повторный поиск, сохранение избранного/заметки, отсутствие дублей и отображение `aiGenerated`. Убедиться, что секреты, cookie, заметки и полный ответ модели отсутствуют в логах.
7. Дополнить корневой README: назначение, архитектура, настройка секретов, команды запуска, миграции, демонстрационный сценарий, ограничения данных, резервное копирование PostgreSQL и ротация ключа.
8. Разместить работающий прототип, получить проверяемые ссылки на него и репозиторий. Подготовить краткое сообщение HR о задаче сервиса, работе поиска и значении статуса `external`.

## Критерии завершения

- Все семь критериев приёмки из [ТЗ](../technical-specification.md) пройдены на опубликованном прототипе.
- У пользователя есть ссылка на работающий прототип и ссылка на репозиторий; запуск по README воспроизводится в чистом окружении.
- Поиск возвращает до 20 лидов, создаёт отдельный JSON-профиль для каждого и сохраняет успешные профили независимо от сбоев других; база работает без провайдера.
- Понятные сообщения об ошибках позволяют повторить действие; сбой провайдера не повреждает сохранённые записи.
- Сообщение HR готово к отправке вместе со ссылками и кратко объясняет ограничения неподтверждённых сведений.
