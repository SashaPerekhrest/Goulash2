# План разработки прототипа

План основан на [техническом задании](../technical-specification.md), [архитектуре](../architecture.md), [схеме работы](../application-flow.md) и [API-контрактах](../api-contracts.md). Спринт здесь — законченный этап с проверяемым результатом. Продолжительность зависит от состава команды и доступности провайдера с веб-поиском; календарные сроки в документации не заданы.

## Сквозные правила

- Контракт `/api/v1` и формат `application/problem+json` берутся из [api-contracts.md](../api-contracts.md). При изменении DTO или поведения одновременно обновляются контракт и связанные спринты.
- В каждом спринте проверяются затронутые сценарии и ошибки. Секреты, cookie, заметки и полный ответ модели не попадают в логи и клиентскую сборку.
- Внешнее значение сохраняется только с конкретной страницей, подтверждающим фрагментом и датой получения. `official` назначает сервер после проверки домена; значение только со сторонней страницы получает `external`, а без подтверждающего фрагмента остаётся `missing`.
- Избранное и заметка относятся к общей базе и не изменяются при повторном поиске.
- К концу каждого спринта остаётся работоспособное состояние проекта, миграции применяются без ручного исправления данных, а незавершённая функциональность не выдаётся за готовую.

| Критерий из ТЗ | Основные спринты |
| --- | --- |
| До пяти валидных поставщиков, запрет пустого поиска | 03–04, 07 |
| Сохранение без дублей и потери избранного/заметки | 01, 04–05 |

| Настройка ключа без раскрытия | 02, 06 |
| Запуск через Docker Compose и миграции | 01, 09 |
| Понятные ошибки и безопасная обработка частичного ответа | 03–04, 07, 09 |

Сквозная приёмка всех семи критериев и демонстрационного пути проводится в [спринте 09](09-release-and-handoff.md).
