# Спринт 03. Провайдер с веб-поиском и проверка доказательств

## Цель

Подключить минимум один реальный ИИ-провайдер, способный вернуть актуальные веб-источники, и построить проверяемый путь от страницы до сохранённого факта.

## Работы

1. Выбрать адаптер и модель с реальным веб-поиском; зафиксировать поддерживаемые идентификаторы, формат ответа, доступность URL и фрагментов страниц. Если провайдер не даёт фрагменты веб-инструмента отдельно от текста модели, он не подходит для сохранения поставщиков.
2. Реализовать `ISupplierDiscoveryProvider.DiscoverAsync(query, filters, limit, cancellationToken)` и `Goulash.Application.IAiProviderAdapter.CheckConnectionAsync(model, apiKey, cancellationToken)`, возвращающий `AiProviderCheckResult(Connected, WebSearchAvailable)`. Зарегистрировать адаптер в DI; передавать лимит пять, структурированные условия и запрет на домысливание полей.
3. Настроить проверку подключения `POST /ai/settings/check`: минимальный запрос подтверждает и соединение, и доступ к веб-источникам. Ошибка проверки не удаляет настройки.
4. Ограничить время внешнего запроса (по умолчанию 45 секунд), размер ответа и число повторов при временном сбое (не более одного до сохранения). Передавать отмену провайдеру, когда это возможно.
5. Разобрать общий JSON и отдельные записи раздельно. Неверная общая схема даёт `PROVIDER_INVALID_RESPONSE`; отдельная ошибочная запись не мешает обработать остальные.
6. Проверять название, URL, длины полей и фрагмент страницы для каждого факта. URL должен быть абсолютным `http`/`https`; локальные и служебные адреса не допускаются. Факт без подтверждающего фрагмента не сохранять; если не подтверждено название, отклонять всю запись поставщика.
7. Установить официальный домен по подтверждённой связи сайта и компании, учитывая поддомены и публичные суффиксы. Статус `official` назначает сервер только факту с этого домена; сведения со сторонних страниц получают `external`. При расхождениях сохранять альтернативные наблюдения.
8. Нормализовать города, категории, денежные суммы, единицы, контакты и домены без потери исходной формулировки и ссылок. Для каждого подтверждённого значения сохранять URL, заголовок, `excerpt`, тип источника и дату получения.

## Проверяемый результат

- Проверка настроенного провайдера возвращает `connected` и `webSearchAvailable`; при отсутствии ключа и сбоях возвращается соответствующий Problem Details.
- Значение без фрагмента веб-источника не попадает в факты; ответ модели сам по себе не становится источником.
- Сторонний источник не превращается в `official` по заявлению модели. При расхождении официальный факт выбирается текущим, сторонний остаётся альтернативой.
- Тайм-аут, некорректная оболочка ответа и отказ провайдера не изменяют сведения о поставщиках; диагностическая запись о неудачном запуске допустима. Частично невалидные записи можно отделить от валидных.

## Передача в следующий спринт

Сервис поиска получает структурированные записи с проверенными доказательствами, статусами и диагностируемыми ошибками. Дедупликация и транзакционное сохранение выполняются в спринте 04.
