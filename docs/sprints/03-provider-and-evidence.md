# Спринт 03. Провайдер веб-поиска и двухэтапное исследование

## Цель

Подключить веб-поиск у поддерживаемых ИИ-провайдеров и получать подробный структурированный профиль поставщика в два запроса: список лидов, затем отдельный JSON-профиль каждого лида.

## Работы

1. Реализовать адаптеры Perplexity Sonar и Polza.ai с поддержкой веб-поиска, JSON-ответов, URL-цитат и тайм-аутов.
2. Описать отдельные схемы ответов: первый запрос возвращает до 20 пар «название + сайт», второй — один полный профиль поставщика.
3. Передавать запрос и все заданные фильтры в первый поиск как требования к отбору лидов; не применять фильтры повторно после получения профиля.
4. Перед профилем загрузить с сайта лида до восьми публичных HTML-страниц с ограничениями по времени, объёму и хосту. Для второго запроса передать собранный текст и направить веб-поиск провайдера на домен поставщика.
5. Переносить валидный профильный JSON в факты со статусом `aiGenerated`. Не выполнять сверку фактов с цитатами, их оценку или бизнес-отбраковку профиля.
6. Сохранять страницы и цитаты на уровне поставщика как справочные ссылки. Не выдавать их за доказательство каждого отдельного поля.
7. Изолировать ошибку профильного запроса: учитывать её в `failedProfileCount` и продолжать обработку других лидов.

## Проверяемый результат

- Пустой список после первого запроса завершает поиск без вызовов обогащения.
- Для каждого лида отправляется отдельный запрос; профиль с пропущенными необязательными полями сохраняется.
- Фильтры присутствуют в первом запросе и не запускают серверную фильтрацию уже полученных профилей.
- Профильный вызов ограничивает веб-поиск сайтом лида, когда провайдер поддерживает такое ограничение.
- Ошибка одного профиля не отменяет успешные профили; некорректная оболочка первого списка завершает запуск ошибкой провайдера.

## Реализация в проекте

- `SupplierDiscoveryService` выполняет этапы поиска и преобразует ответы в DTO профиля.
- `SupplierSiteResearcher` загружает ограниченный набор публичных страниц сайта до профильного запроса.
- `SupplierDiscoveryJson` хранит схемы JSON для двух этапов.
- `PerplexityProviderAdapter` и `PolzaProviderAdapter` используют общий двухэтапный контракт.
- `SupplierDiscoveryEvidencePolicy` применяется только к публичным URL и справочным ссылкам; факт-матчер и прежние парсеры удалены.
