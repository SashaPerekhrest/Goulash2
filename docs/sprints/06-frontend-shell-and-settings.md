# Спринт 06. Каркас интерфейса, вход и настройки

## Цель

Создать целостную оболочку React-приложения с защищёнными страницами, входом и управлением интеграцией.

## Работы

1. Настроить маршруты `/login`, `/discover`, `/suppliers`, `/suppliers/:id`, `/settings/integration`, навигацию и состояние загрузки страниц. Защищённые страницы не показывать до проверки сессии.
2. Реализовать API-клиент с cookie, получением CSRF-токена, заголовком `X-CSRF-Token` для изменяющих запросов, единым разбором Problem Details и обработкой `401` с переходом на вход.
3. Сделать страницу входа: получить CSRF-токен до `POST /auth/login`, показать ошибки без раскрытия внутренних данных, после успешного входа открыть доступные разделы. Добавить выход.
4. Сделать страницу интеграции: загрузить `GET /ai/providers` и `GET /ai/settings`, выбрать адаптер и модель, ввести или заменить ключ, сохранить настройки, удалить ключ.
5. Показывать только факт наличия ключа и его маску. При смене провайдера требовать новый ключ. Не сохранять секрет в URL, браузерном постоянном хранилище или логах интерфейса.
6. Подключить `POST /ai/settings/check` и показать отдельно состояние соединения и доступности веб-поиска. При отсутствии настройки дать понятный переход из поиска в настройки.
7. Подготовить общие компоненты формы, карточки, пустого состояния, индикатора загрузки, уведомления об ошибке и безопасной внешней ссылки (`rel="noopener noreferrer"`).

## Проверяемый результат

- Пользователь может войти, перезагрузить страницу с действующей сессией, выйти и получить переход на вход при `401`.
- Ключ создаётся, меняется и удаляется через интерфейс; после перезагрузки видны только маска и `hasApiKey`.
- Проверка подключения показывает результат доступа к источникам или конкретную ошибку. Доступность сохранённой базы без ключа проверяется после реализации API и страницы базы в спринтах 05 и 08.
- Навигация работает по прямым ссылкам и после обновления страницы; внешний URL открывается безопасно.
