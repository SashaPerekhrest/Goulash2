# Техническое задание: поиск поставщиков для food-направления

## 1. Назначение и границы первой версии

Веб-сервис помогает находить поставщиков ингредиентов, готовой продукции, упаковки и других товаров для пищевого бизнеса, сохранять найденные компании и выбирать, с кем связаться. Целевая аудитория прототипа — один пользователь или небольшая команда с общей базой. Для публичной демонстрации доступ к приложению защищается учётной записью администратора; роли, совместная работа и разграничение избранного по пользователям в первую версию не входят.

По исходному заданию сервис должен искать по категории и региону, показывать контакты и источники, помогать сравнивать условия. Дополнительные данные — минимальный заказ, цена, сертификаты, доставка, регионы работы и заметки — включены в первую версию, если они доступны в источниках.

## 2. Основной сценарий

1. Пользователь задаёт текстовый запрос и/или фильтры на странице «Найти поставщиков».
2. Первый запрос к веб-поиску получает текст и пользовательские фильтры и возвращает до 20 лидов.
3. Для каждого лида отдельный запрос исследует сайт и возвращает полный JSON-профиль.
4. Backend переводит JSON-профили в сущности базы без проверки фактов и повторной фильтрации.
5. Страница показывает карточки найденных компаний и обозначает данные как извлечённые моделью.
6. Пользователь открывает карточку, изучает профиль и справочные ссылки, добавляет компанию в избранное или оставляет заметку.
7. Страница «База поставщиков» показывает сохранённые компании и выполняет поиск локально, без ИИ.

## 3. Страницы и поведение

### 3.1. Поиск новых поставщиков

Начальное состояние: только поле запроса, конструктор фильтров и подсказка; карточек нет. Поле запроса допускает свободный текст. Фильтры: город/регион, категория или вид товара, диапазон цены, максимальный срок доставки, минимальный/максимальный объём заказа при наличии сопоставимых единиц. Достаточно текста или одного фильтра для запуска поиска; пустой запрос без фильтров запрещён.

Изменения запускают поиск после задержки 700 мс. Кнопка «Найти» запускает его сразу. Новый ввод отменяет ожидание предыдущего запуска; одновременно от одной страницы отправляется не более одного запроса. Во время выполнения видны индикатор и параметры запущенного поиска. Повторение того же поиска доступно явной кнопкой.

Первый этап возвращает до 20 компаний. Карточка содержит название, город, товары, краткую цену/условия доставки при наличии, сайт или контакт, отметку избранного и признак наличия сведений, извлечённых моделью. Предусмотрены состояния «ничего не найдено», «провайдер не настроен», «ошибка/тайм-аут», «часть профилей не получена». История поисковых запросов не является обязательной для первой версии.

Фильтры передаются только первому запросу как критерии поиска списка. Backend не сравнивает их с JSON второго этапа и не отклоняет поставщиков по результатам такой проверки. Числовые значения нормализуются для записи проекций и последующего локального поиска в каталоге. Значения извлекает модель и отдельно не сверяет их с текстом страниц; профильные факты помечаются `aiGenerated`, а ссылки на страницы являются справочным контекстом. Валюта и единица измерения автоматически не преобразуются при локальной фильтрации.

### 3.2. База поставщиков

Сразу после открытия отображается первая страница записей. Доступны текстовый поиск по названию/товарам, те же применимые фильтры, фильтр «Избранное», сортировка по дате добавления и названию, переключение избранного и переход в детали. Единообразные карточки с товарами, ценой и доставкой помогают сравнить найденные варианты; отдельный экран сравнения в первую версию не входит. Запросы выполняются только к внутренней базе. Пагинация серверная, размер страницы по умолчанию 20, допустимо 10–50.

### 3.3. Детали поставщика

Отображаются название, описание, товары, адрес, регионы работы, контакты, сайт, цены с валютой и единицей измерения, минимальный заказ, сроки и условия доставки, сертификаты/документы, фотографии по ссылкам, справочные источники и дата обновления. Заполненное поле имеет статус, значение и дату наблюдения; отдельные ссылки на подтверждение факта не обещаются. Новые значения имеют статус `aiGenerated`. Избранное и заметка общие для пользователей общей базы; заметку можно изменить.

Каждое поле имеет один из следующих статусов:

| Состояние | Условие | Текст в интерфейсе |
| --- | --- | --- |
| `official` | URL источника относится к домену сайта компании | «Извлечено моделью с сайта компании» |
| `external` | URL источника относится к внешнему домену | «Извлечено моделью из внешней страницы» |
| `aiGenerated` | Значение возвращено моделью и отдельно не проверялось | «Собрано моделью, не проверено» |
| `missing` | Надёжного значения не найдено | «Нет данных» |

Ссылки и сниппеты сохраняются на уровне поставщика и служат для перехода, а не доказательством каждого поля. Статусы `official` и `external` могут встречаться у ранее сохранённых сведений. Не следует показывать пустые изображения или подставлять придуманные контакты.

### 3.4. Настройки интеграции

Пользователь выбирает одного из поддерживаемых адаптеров провайдера, указывает модель и API-ключ, сохраняет настройки и может проверить подключение. Интерфейс показывает, настроен ли ключ, но не возвращает его значение после сохранения. Предусмотрены замена и удаление ключа. Поиск недоступен, если провайдер не настроен или не поддерживает получение актуальных источников.

## 4. Получение и качество данных

Backend ставит задание в очередь. Первый запрос получает текст и фильтры и ищет до 20 лидов. Для каждого лида приложение загружает до восьми публичных страниц его сайта и отправляет отдельный профильный веб-запрос. Модель возвращает JSON-профиль; отсутствующие поля остаются пустыми. Профили не фильтруются после обогащения. UI показывает состояние, прогресс и число ошибок профильных запросов.

Backend разбирает JSON в сущности и нормализует поисковые проекции. Он не сравнивает значения фактов со страницами и не применяет пользовательские фильтры после профильного этапа. Технические проверки ограничены структурой JSON для преобразования, безопасными публичными URL и лимитами сетевой загрузки. Ссылки и сниппеты хранятся на уровне поставщика как справочная информация. Отсутствие необязательного поля не отклоняет профиль, а сбой одного профильного запроса не блокирует остальные.

Дубли ищутся сначала по нормализованному домену выбранного сайта. Если новый домен не найден в базе, проверяется запись без домена с тем же нормализованным названием и регионом; неоднозначные совпадения не сливаются автоматически. Повторный поиск обновляет факты и источники, но сохраняет избранное и заметку. Разные наблюдения остаются альтернативными фактами. Фотографии хранятся как URL страниц; отсутствие фотографии допустимо.

Сервис показывает собранную информацию для предварительного выбора, а не гарантирует актуальность коммерческих условий. Пользователь видит дату получения сведений и может перейти к источнику перед обращением к компании.

## 5. Технологии и ограничения

- Backend: ASP.NET Core Web API, EF Core, PostgreSQL.
- Frontend: React с TypeScript.
- Развёртывание: Docker Compose с контейнерами frontend, backend, PostgreSQL.
- API-ключи и пароль администратора не включаются в репозиторий. Ключ хранится на сервере в зашифрованном виде; мастер-ключ передаётся через переменную окружения/секрет окружения.
- Все внешние URL при открытии проверяются на допустимую схему `https`/`http`; сервер не загружает фотографии по произвольным адресам.
- Внешние обращения имеют тайм-аут, ограничение размера ответа и диагностируемые ошибки. Секреты и полный текст ответа провайдера не пишутся в логи.

Архитектурные решения и схема данных описаны в [architecture.md](architecture.md), HTTP-контракты — в [api-contracts.md](api-contracts.md), последовательности работы — в [application-flow.md](application-flow.md).

## 6. Критерии приёмки

1. Первый поиск с текстом и/или фильтром возвращает до 20 лидов; каждый лид обогащается отдельным JSON-запросом.
2. Результаты сохраняются, повторный поиск не создаёт дубликаты и не стирает избранное/заметки.
3. База открывается с сохранёнными данными, ищет и фильтрует без обращения к ИИ, поддерживает пагинацию.
4. В деталях видны значения, дата сбора и общий список справочных URL либо «Нет данных»; новые факты имеют статус `aiGenerated`.
5. Ключ настраивается через UI, не раскрывается в ответах API и не попадает в клиентскую сборку.
6. Приложение запускается через Docker Compose по README; миграции применяются при развёртывании.
7. Ошибка первого запроса отображается понятно; сбой отдельного профильного запроса не отменяет успешно полученные профили.
