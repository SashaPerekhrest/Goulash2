# Гуляш

Развёртывание рядом с Goulash1 через GitHub Actions, GHCR, Docker Compose и хостовый Nginx описано в [docs/deploy-github-actions.md](docs/deploy-github-actions.md).

Прототип сервиса поиска поставщиков для food-бизнеса. Реализованы API поиска и сохранения поставщиков, локальный каталог с фильтрами и пагинацией, детали с источниками, избранное и заметки, а также безопасная авторизация и настройки интеграции: ASP.NET Core API, PostgreSQL, модель фактов и источников, EF Core-миграции, проверка готовности, сессия администратора, CSRF и шифрование ключа провайдера.

## Запуск всего приложения

Нужны Docker Compose и доступ к Docker Engine.

1. Скопируйте `.env.example` в `.env` и задайте случайные значения для `POSTGRES_PASSWORD` и `ADMIN_INITIAL_PASSWORD`. Создайте `AI_ENCRYPTION_KEY` как Base64-представление случайных 32 байт (например, `openssl rand -base64 32`). Мастер-ключ должен оставаться неизменным, пока в базе есть зашифрованные ключи. Для локального запуска по HTTP на `localhost` добавьте в `.env` `ASPNETCORE_ENVIRONMENT=Development`.
2. Выполните `docker compose up --build`.
3. Откройте `http://localhost:3000`. API готов, когда `http://localhost:8080/api/v1/health/ready` отвечает `200`.
4. Фактическая OpenAPI-схема доступна на `http://localhost:8080/openapi/v1.json`.

Для HTTPS-развёртывания укажите публичный домен в `APP_DOMAIN`, направьте его DNS-запись на сервер и откройте на нём входящие порты 80 и 443. Запустите стек командой `docker compose --profile production up --build -d` и откройте `https://your-domain.example` (подставьте значение `APP_DOMAIN`). Caddy завершает TLS и автоматически получает и обновляет публичный сертификат; сертификаты хранятся в отдельных именованных томах. Доступ к API и PostgreSQL снаружи хоста закрыт привязкой портов к `127.0.0.1`. `Production` выставляет cookie с `Secure`; локальный HTTP допускается только с `ASPNETCORE_ENVIRONMENT=Development`.

PostgreSQL хранит данные в именованном volume `postgres_data`. API применяет неприменённые EF Core-миграции при старте; история миграций хранится в `__EFMigrationsHistory`, поэтому повторный запуск не создаёт схему заново. Для небольшого прототипа миграции запускаются одним экземпляром приложения; для окружения с несколькими репликами используйте отдельный шаг миграции перед выпуском.

### Резервная копия и восстановление PostgreSQL

Команда ниже создаёт архивный дамп на хосте, не передавая пароль базы в аргументах командной строки:

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > goulash-backup.dump
```

Перед восстановлением остановите API и убедитесь, что выбрали нужную базу. Для восстановления поверх текущих данных выполните:

```sh
docker compose stop api
docker compose exec -T db sh -c 'pg_restore --clean --if-exists --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < goulash-backup.dump
docker compose start api
```

Храните дамп отдельно от сервера и регулярно проверяйте восстановление на отдельном экземпляре PostgreSQL.

### Ротация мастер-ключа

`AI_ENCRYPTION_KEY` шифрует API-ключ провайдера, сохранённый в базе. Замена мастер-ключа без подготовки сделает текущий зашифрованный ключ нечитаемым. Сначала сохраните ключ провайдера в менеджере секретов и сделайте резервную копию базы. Удалите ключ в настройках интеграции, пока старый мастер-ключ ещё действует. Затем замените `AI_ENCRYPTION_KEY` в секретах окружения, перезапустите API и введите ключ провайдера заново. Не добавляйте секреты в репозиторий.

Файл `.env` игнорируется Git. Значения `.env.example` — только placeholders. Пароль администратора и мастер-ключ обязательны при запуске. Compose по умолчанию использует `Production` и выдаёт session и CSRF cookie с `Secure`; опубликованная среда должна обслуживаться по HTTPS. `Development` допускается только для локального HTTP. Сессия длится 8 часов без продления активности и отзывается при выходе. Хранилище активных сессий находится в памяти одного процесса: перезапуск API завершает все сессии. Вход ограничен пятью попытками за 15 минут с одного IP.

API авторизации: `GET /api/v1/auth/csrf`, `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, `GET /api/v1/auth/session`. Перед каждым `POST`, `PUT`, `PATCH` или `DELETE` клиент получает CSRF-токен и отправляет его в `X-CSRF-Token`. Настройки доступны по `/api/v1/ai/providers` и `/api/v1/ai/settings`; ключ шифруется AES-256-GCM с `AI_ENCRYPTION_KEY`, а API возвращает только маску. Доступны Perplexity Sonar (`providerId: perplexity`) с моделями `sonar`, `sonar-pro`, `sonar-deep-research`, `sonar-reasoning-pro` и Polza.ai (`providerId: polza`). Для Polza укажите ID модели из каталога в формате `vendor/model` (например, `openai/gpt-4o`). По желанию можно указать точное название маршрут-провайдера из каталога Polza; пустое поле оставляет выбор маршрута автоматике Polza. Поиск состоит из двух этапов: первый веб-запрос получает исходный текст и фильтры и возвращает до 20 названий и сайтов; для каждого поставщика приложение загружает до восьми страниц и отдельным веб-запросом получает профиль в JSON. Общий базовый промпт и шаблон второго запроса для профиля редактируются в разделе интеграции; шаблон поддерживает `{{supplierName}}`, `{{websiteUrl}}` и `{{websitePages}}`. Фильтры не применяются повторно после обогащения. `POST /api/v1/discoveries` ставит задание в очередь и возвращает `discoveryId`; frontend опрашивает `GET /api/v1/discoveries/{id}` до готового результата. Для Perplexity профильный веб-поиск ограничивается сайтом кандидата; Polza получает домен в поисковой строке. Backend не сверяет факты с цитатами: профиль сохраняется со статусом `aiGenerated`, а URL страниц и сниппеты доступны как общий справочный список поставщика. Ошибки отдельных профильных запросов считаются в `failedProfileCount` и не останавливают остальные. Внешний вызов ограничен тайм-аутом 45 секунд и ответом 2 MiB. Проверка подключения делает отдельный короткий веб-запрос.

Каталог доступен по `GET /api/v1/suppliers`; фильтры, сортировка и пагинация работают только по сохранённым данным и не обращаются к ИИ. Детали компании возвращаются через `GET /api/v1/suppliers/{id}` с датой наблюдения каждого поля и общим списком справочных ссылок. Избранное и общая заметка изменяются через `PUT /api/v1/suppliers/{id}/favorite` и `PUT /api/v1/suppliers/{id}/note`.

## Локальная разработка

Для frontend: из `frontend` выполните `npm ci`, затем `npm run dev`. Vite проксирует `/api` и `/openapi` на `http://localhost:8080`.

Для backend нужна доступная PostgreSQL. Перед `dotnet run --project backend/Api/Goulash.Api.csproj` задайте переменные `Database__Host`, `Database__Port`, `Database__Name`, `Database__User` и `Database__Password`. API автоматически применяет миграции при старте.

Командный инструмент EF Core закреплён как локальный tool в `backend/.config/dotnet-tools.json`. Для новой миграции восстановите его через `dotnet tool restore`, затем из `backend` выполните `dotnet tool run dotnet-ef migrations add <MigrationName> --project Infrastructure/Goulash.Infrastructure.csproj --startup-project Api/Goulash.Api.csproj --output-dir Persistence/Migrations`.

## Структура

- `backend/Api` — HTTP-маршруты, ошибки и OpenAPI.
- `backend/Application` — правила идентификации поставщиков и сценарии приложения.
- `backend/Domain` — сущности и правила происхождения фактов.
- `backend/Infrastructure` — PostgreSQL, EF Core, транзакции и миграции.
- `frontend/src/pages` — страницы и маршруты SPA.
- `frontend/src/features` — папка для функциональных модулей следующих спринтов.
- `frontend/src/shared` — общий API-клиент, каркас приложения и UI.

## Данные и происхождение

Новый поиск сохраняет сведения из JSON-профиля со статусом `aiGenerated`; `missing` вычисляется при отсутствии текущего значения. Факты не сверяются с текстом страниц и не получают индивидуальных ссылок-доказательств. Страницы сайта и доступные цитаты сохраняются в общем списке источников поставщика. Нормализация формирует индексируемые проекции товаров и цен для локального каталога. Повторный поиск обновляет профиль, сохраняя избранное и заметку.

Уникальный индекс официального домена защищает от его конкурентного дублирования. Для кандидатов с совпадающими нормализованным названием и регионом `SupplierIdentityLock` даёт транзакционную PostgreSQL-блокировку. `SupplierDataTransaction` сохраняет факты, источники и индексируемые проекции в одной транзакции.

Цены, доступность и другие условия — снимок, сформированный моделью на дату сбора, а не гарантия текущего предложения. Перед коммерческим решением их нужно проверить у поставщика. Список URL помогает открыть сайт и продолжить проверку вручную.

## Демонстрационный сценарий и передача

После входа откройте «Настройки интеграции», выберите Perplexity или Polza.ai, сохраните API-ключ и проверьте веб-поиск. Для Polza укажите ID модели (например, `openai/gpt-4o`), при необходимости задайте маршрут-провайдер. На странице «Найти поставщиков» введите категорию и регион, откройте карточку, проверьте источники и статусы полей, добавьте компанию в избранное и сохраните общую заметку. Добавьте подходящие компании кнопкой «Сравнить» в поиске или базе, затем откройте раздел «Сравнение». Он показывает профили колонками; список поставщиков и заметки сравнения хранятся в `localStorage`, а правки заметок сравнения не изменяют общие заметки в базе. Затем найдите компанию в «Базе поставщиков» и убедитесь, что избранное и общая заметка сохранились. Текст для HR подготовлен в [docs/hr-handoff.md](docs/hr-handoff.md).

Результаты локальной проверки выпуска и оставшиеся шаги для проверки опубликованного экземпляра описаны в [docs/release-verification.md](docs/release-verification.md).

Публичную ссылку можно добавить после запуска проекта на сервере с доменом, секретами и доступом к Docker Engine. В сообщении HR укажите фактические HTTPS-адрес приложения и URL репозитория.

## API ошибки и логи

Ошибки отдаются как `application/problem+json` с `code` и `traceId`. Готовность проверяет PostgreSQL отдельным запросом и остаётся доступной без сессии. Логи содержат событие и trace ID, но не тело запросов, содержимое ответов модели, заметки, cookie, пароль, CSRF-токен, ключи или исключения драйвера с деталями подключения.
